**Specific Exercises:**

- Creating a project with gradle-managed dependencies in Eclipse  
    
  The biggest problem they have is that the version of JUnit they need depends on the exact version of Eclipse they have installed, and using the wrong version will cause the example test to crash with a linker error (NoClassFound, NoMethodFound, etc). This will be different for different students \- instructions are in the README  
    
  The template repo uses 5.10.2 because that's what my local version of Eclipse uses, feel free to change it.

- Write a simple unit test (exercise1)  
- Write a fuzzy test (exercise2)  
- Debugging example (debugdemo)  
- Debug some broken math (exercise3)

**Details:**

Technically, they don’t need the “debugging” part for checkpoint 3 (and in a perfect world they’d learn most of this in CS1), but it’s as good a point as any to introduce them to the concept of breakpoints. As CS1 & CS2 start including more hands-on programming, the IDE and tooling-specific parts can get removed (what is a breakpoint, how do you step over a line, how do you find and fix bugs beyond “stare at the code”)

Up to you about the Mockito.verify slide \- this is a common pitfall for students who prefer to ask chatGPT rather than look at the actual course material. I didn't blacklist it in the checkpoint tests, but it might be worth adding to those instead, and then just remove from the lecture slides (it does break up the lecture flow)

For the exercises/demos, I usually post whatever code we end up with to Brightspace rather than the example solutions, since sometimes questions during class have the code go in different directions (I just look at the solutions before class to remind myself of what I was thinking of for each question). If you do post ad-hoc code, make sure to **warn them** that they can't just mindlessly copy the sample code onto exams, demonstrations of common mistakes and all. I consider the "can't mindlessly copy" to be a feature, not a bug.
