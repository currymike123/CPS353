**Details**

Some of the intro material about pointers can be removed over time if that gets covered in CS1 & CS2.

To explain the Magritte painting ("this is not a pipe") - "pointers" vs "object pointed to" is a pretty exact analog to Derrida's signifier vs signified in written language ("the territory is not the map" is another phrasing I've seen that can be helpful). Mostly I include it as a shout-out to the value of a liberal arts education, but there's sometimes one or two students who find it extremely helpful for understanding why the 'final' keyword seems to work differently for an ArrayList vs an int, or when parameters can be modified in a way visible in the calling scope vs. not (or, for threading, what data has one copy per thread and what data is shared).

Concurrency library vs low-level Thread calls: I was assuming the library would make it easier for students to focus on the interesting concepts around threading, but it may actually hide too much detail, I didn't get the sense that this material clicked super well. Spending an extra day getting more into the mechanics here and having them actually pass exception/return data between threads themselves might be worth it.

Multithreading bugs: Useful time to talk about workarounds vs fixes; when dealing with a production p0, get the system back online first, then go figure out and fix the root cause. Single-threading multithreaded code will always fix multithreaded bugs, it just may/will make things slow
