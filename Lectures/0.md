# Lecture 0: Course Introduction

---

## Welcome to CPS 353!

**CPS 353: Software Construction**

This course is your gateway to mastering modern software engineering practices. We’ll move beyond writing simple scripts and dive into building robust, scalable, and maintainable applications.

Our goal is not just to teach you to code, but to teach you how to be an **effective software engineer**.

---

## The "Missing Semester"

Most CS programs teach you the theory: algorithms, data structures, and languages. They don't always teach you the **craft** of software development.

- How do you use your tools effectively?
- How do you collaborate with a team on a large codebase?
- How do you ensure your code will still be usable a year from now?

This course aims to fill that gap, inspired by MIT's "Missing Semester of Your CS Education."

---

## Course Philosophy, Part 1

This course is guided by three core principles for building robust software, drawn from best practices at companies like Google.

1.  **Safe from Bugs:** Correctness and robustness are paramount.
2.  **Easy to Understand:** Code must be readable and maintainable for others (and your future self!).
3.  **Ready for Change:** Software is not static. It must be designed to adapt to new requirements.

---

## Philosophy: "Safe from Bugs"

- **What it means:** Writing code that behaves as expected, even in unexpected circumstances. Preventing errors before they happen.
- **Example:** Instead of hoping a user provides valid input, you validate it rigorously. Instead of assuming a network call will succeed, you handle the failure case gracefully.
- **In this course:** We will emphasize testing (JUnit, TDD) and debugging techniques to build a habit of creating resilient code.

---

## Philosophy: "Easy to Understand"

- **What it means:** Code is read far more often than it is written. Your code should be a clear expression of its intent.
- **Example:** Choosing clear variable names (`elapsedTimeInDays` vs. `d`), writing concise functions that do one thing well, and documenting non-obvious logic.
- **In this course:** We will focus on code reviews, documentation (Javadoc), and following consistent style conventions.

---

## Philosophy: "Ready for Change"

- **What it means:** The only constant in software is change. Good design anticipates change and makes it less painful.
- **Example:** Instead of hardcoding a value like a tax rate throughout your application, you define it in a single, well-known location. This makes updates easy and safe.
- **In this course:** We will explore concepts like dependency management (Maven/Gradle) and CI/CD that allow us to confidently introduce and ship changes.

---

## What You Will Learn (The Toolbox)

- **The Command-Line:** Your fundamental tool (Bash, Shell scripting).
- **Development Environment:** VS Code, Vim emulation, and professional setup.
- **Version Control:** Mastering Git and GitHub for collaboration.
- **Build & Packaging:** Using Maven/Gradle to build and manage Java applications.
- **Testing:** Writing effective unit, integration, and end-to-end tests (JUnit).
- **CI/CD:** Automating your development workflow with GitHub Actions.
- **Debugging & Profiling:** Finding and fixing bugs and performance issues.

---

## The Term Project: A Living Application

Throughout the semester, you will build and evolve a single, scalable web service using Java and Spring Boot.

- **Part 1: Initial Setup & REST API:** Build the core application.
- **Part 2: CI/CD Integration:** Create an automated pipeline for testing and builds.
- **Part 3: Advanced Features (gRPC):** Extend your service with new capabilities.
- **Part 4: Final Polish & Deployment:** Prepare your application for "production."

This project is designed to be a realistic simulation of working on a long-lived software project.
