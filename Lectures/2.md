# Lecture 2: Introduction to Git & Basic Commands

---

## An Analogy: Saving Your Game

Think of version control like a sophisticated "save" system for your project.

- A simple `Ctrl+S` **saves** your file.
- A Git **commit** is like a named "save slot" for your *entire project*. It has a timestamp, an author, and a message describing what changed.

You're not just saving files; you're saving coherent snapshots of your project's history.

---

## Centralized vs. Distributed

**Centralized (e.g., Subversion):** One central server holds all the history.
- **Con:** Single point of failure. Must be online to commit.

```
+-----------+         +-----------+
| Developer | <-----> |   SVN     | <-----> | Developer |
|    A      |         |  Server   |         |    B      |
+-----------+         +-----------+         +-----------+
```

**Distributed (e.g., Git):** Everyone has a full copy of the history.
- **Pro:** Work offline, faster operations, more resilient.

```
+-----------+         +-----------+         +-----------+
| Developer | <-----> | Developer | <-----> | Developer |
| A's Repo  |         |  B's Repo |         |  C's Repo |
+-----------+         +-----------+         +-----------+
```

---

## The Three Areas: A Visual

This is the most important concept in Git.

```
+------------------+     git add     +----------------+     git commit    +----------------+
|                  | --------------> |                | ---------------> |                |
|  Working         |                 |  Staging Area  |                 |   Repository   |
|  Directory       | <-------------- |     (Index)    | <-------------- | (.git folder)  |
|                  |   git checkout  |                |     git reset   |                |
| (untracked files)|                 | (staged files) |                 | (committed     |
| (modified files) |                 |                |                 |  snapshots)    |
+------------------+                 +----------------+                 +----------------+
```
- **Working Directory:** Your active files.
- **Staging Area:** The "on deck" circle for your next commit.
- **Repository:** The permanent history of your project.

## Workshop Setup

Let's do this live. Open your terminal and follow along.

We are going to build a simple Java project and track it with Git.

---

### Step 1: Create the Project Directory

Command:
```bash
mkdir my-first-git-project
cd my-first-git-project
```

Output:
(Your shell prompt should now show you are in the `my-first-git-project` directory).

---

### Step 2: Initialize the Git Repository

Command:
```bash
git init
```

Output:
```
Initialized empty Git repository in /home/mike/Desktop/CPS353/my-first-git-project/.git/
```
This creates the hidden `.git` directory.

---

### Inside the `.git` directory

Let's peek inside (you don't normally need to do this).

Command:
```bash
ls -F .git
```

Output:
```
branches/  config  description  HEAD  hooks/  info/  objects/  refs/
```
- `HEAD`: Points to the branch you are currently on.
- `config`: Your repository-specific configuration.
- `objects/`: Stores all your commits and files.
- `hooks/`: For running custom scripts on Git events.

---

### Step 3: Check the Status

`git status` is your best friend. It tells you the current state of your project.

Command:
```bash
git status
```

Output:
```
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)
```
This tells us we are on the `main` branch and have no changes.

---

### Step 4: Create a `.gitignore`

We need to tell Git to ignore files we don't want to track.

Command:
```bash
echo "*.class" > .gitignore
```
This creates a `.gitignore` file containing the line `*.class`.

---

### Step 5: Check the Status Again

Let's see what `git status` says now.

Command:
```bash
git status
```

Output:
```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .gitignore

nothing added to commit but untracked files present (use "git add" to track)
```
Git sees `.gitignore` as a new, "untracked" file.

---

### Step 6: Stage the `.gitignore`

Let's add `.gitignore` to the staging area for our first commit.

Command:
```bash
git add .gitignore
```

Output:
(No output, which means success!)

---

### Step 7: Check Status After Staging

Command:
```bash
git status
```

Output:
```
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   .gitignore
```
The file is now in the "Changes to be committed" section (the Staging Area).

---

### Step 8: Make Your First Commit

Let's save this snapshot to our history.

Command:
```bash
git commit -m "docs: Add .gitignore for Java class files"
```

Output:
```
[main (root-commit) 1a2b3c4] docs: Add .gitignore for Java class files
 1 file changed, 1 insertion(+)
 create mode 100644 .gitignore
```
`1a2b3c4` is the unique ID (hash) for this commit.

---

### Step 9: Create a Java File

Let's add some actual code.

Command:
```bash
echo 'public class User {}' > User.java
```

---

### Step 10: Status with Untracked Code

Command:
```bash
git status
```

Output:
```
On branch main
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        User.java

nothing added to commit but untracked files present (use "git add" to track)
```
`User.java` is untracked.

---

### Step 11: Compile the Java File

Let's create a `.class` file that we told Git to ignore.

Command:
```bash
javac User.java
```

---

### Step 12: Status with an Ignored File

Command:
```bash
git status
```

Output:
```
On branch main
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        User.java

nothing added to commit but untracked files present (use "git add" to track)
```
Notice that `User.class` is NOT listed! Our `.gitignore` is working.

---

### Step 13: Stage and Commit the User Class

Let's add `User.java` and commit it.

Commands:
```bash
git add User.java
git commit -m "feat: Add initial User class"
```

---

### Step 14: Viewing History with `git log`

Let's see the story of our project so far.

Command:
```bash
git log
```

Output:
```
commit 2d3e4f5... (HEAD -> main)
Author: Mike <mike@example.com>
Date:   Mon Jul 27 14:30:00 2026 -0400

    feat: Add initial User class

commit 1a2b3c4...
Author: Mike <mike@example.com>
Date:   Mon Jul 27 14:25:00 2026 -0400

    docs: Add .gitignore for Java class files
```
---

### Example: `git log --oneline`

A more compact view.

Command:
```bash
git log --oneline
```

Output:
```
2d3e4f5 (HEAD -> main) feat: Add initial User class
1a2b3c4 docs: Add .gitignore for Java class files
```
---

### Step 15: Modify the `User.java` file

Let's add a field to the class.

Command:
```bash
echo 'public class User { private String name; }' > User.java
```
---

### Step 16: Check for Differences with `git diff`

See what has changed since our last commit.

Command:
```bash
git diff
```

Output:
```diff
--- a/User.java
+++ b/User.java
@@ -1 +1 @@
-public class User {}
+public class User { private String name; }

```
`-` shows the old line, `+` shows the new line.

---

### Step 17: Stage the Change

Command:
```bash
git add User.java
```

---

### Step 18: `git diff` vs `git diff --staged`

Now that the change is staged, what do the diff commands show?

Command: `git diff`
Output: (nothing, because there are no *unstaged* changes)

Command: `git diff --staged`
Output:
```diff
--- a/User.java
+++ b/User.java
@@ -1 +1 @@
-public class User {}
+public class User { private String name; }
```
This shows the changes that are *waiting to be committed*.

---

### Step 19: Commit the Final Change

Command:
```bash
git commit -m "feat: Add name field to User"
```
---

### Step 20: Final History Check

Command:
```bash
git log --oneline
```

Output:
```
3f4g5h6 (HEAD -> main) feat: Add name field to User
2d3e4f5 feat: Add initial User class
1a2b3c4 docs: Add .gitignore for Java class files
```
---

## Workshop Summary

We have simulated the core, everyday workflow of a developer using Git:
- Initialize a repo
- Ignore files
- Add and commit a new file
- View the history
- Modify a file
- View the changes
- Stage and commit the modification

This cycle—**Modify, Stage, Commit**—is the fundamental rhythm of Git.
